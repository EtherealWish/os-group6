### 功能模块：虚拟内存页操作

负责人为 2412219-王炳環。

#### 模块功能描述

本模块在已有多级页表框架上完成虚拟地址与物理页之间的映射维护，实现 `page_insert()` 和 `page_remove()`。插入映射时需要处理无映射、同页重映射和异页替换；撤销映射时需要更新引用计数，并在最后一个引用消失后释放物理页。

涉及的代码及依赖如下。

| 文件 | 需要理解或使用的内容 |
|------|--------------------|
| kern/mm/pmm.c | get_pte、get_page、page_insert、page_remove、tlb_invalidate，以及两个页表自检函数 |
| kern/mm/pmm.h | 物理页分配释放接口、pte2page、page2ppn、pte_create、引用计数接口 |
| kern/mm/mmu.h、kern/mm/memlayout.h | 页表位定义、页大小和物理页描述结构，具体定义位置以工程为准 |
| kern/mm/default_pmm.c | 物理页分配器及页面回收行为 |
| libs/riscv.h | RISC-V 架构定义和相关指令环境 |
| tools/test_lab4.c、tools/inject.py、tools/grade.sh | 课程测试内容、临时测试注入与评分流程 |

输入包括页目录、目标虚拟地址、物理页描述符和映射权限。`page_insert()` 成功返回 0，不能取得页表项时返回 `-E_NO_MEM`；`page_remove()` 返回类型为 void，对没有有效映射的地址直接返回。

实现需要同时维护页表项、物理页引用数和 TLB 状态。同页重复映射只改变需要更新的权限，引用数保持原值；替换其他物理页时，撤销旧引用并建立新引用；删除映射时，最后一个引用消失才允许释放数据页。

## 3. page_insert 的三种映射状态

### Case 1：原地址没有有效映射

目标页引用数加一，随后写入新页表项。

### Case 2：原地址映射到另一物理页

### Case 3：原地址已经映射到目标物理页

引用计数保持原值，保留页面有效生命周期。

### Post-Condition

三种状态统一使用 pte_create(page2ppn(page), perm) 写入表项，
再对 la 执行 TLB 失效，成功返回 0。

## 4. page_remove 的映射撤销

### Requirements

1. 使用 get_pte(pgdir, la, 0)。
2. ptep 为 NULL 或表项无效时直接返回。
3. 有效表项通过 pte2page 转为原物理页描述符。
4. 清零页表项，使目标地址旧翻译失效。
5. 原物理页引用数减一，归零时调用 free_page。
6. 再次删除相同地址时，不额外减少引用，不重复释放页面。

### Post-Condition

原地址已无有效映射，剩余共享映射仍持有原物理页的有效引用。

**实现思路与提示词设计**

映射函数的返回值只能表达操作是否成功，要判断实现是否正确，还需要描述操作前后的资源状态。为此，先将虚拟地址 A 对应的映射记为 M(A)，将物理页 P 的引用计数记为 R(P)，再根据旧映射状态划分输入。

本模块维护的引用数变化，可以通过以下关系描述。

| 操作 | 映射变化 | 引用数变化 |
|------|----------|------------|
| 首次映射 | M(A) 从空变为 P | R(P) 增加 1 |
| 同页重映射 | M(A) 仍为 P，权限改变 | R(P) 不变 |
| 异页替换 | M(A) 从 P 变为 Q | R(P) 减少 1，R(Q) 增加 1 |
| 撤销有效映射 | M(A) 从 P 变为空 | R(P) 减少 1 |
| 撤销空映射 | M(A) 仍为空 | 所有相关引用数不变 |

**页面生命周期与别名处理**

同页重映射是本模块最容易产生资源生命周期错误的场景。假设 A 已经指向 P，且 R(P)=1。若实现先无条件删除旧映射，R(P) 会降至 0，物理页被归还给分配器；之后再把 A 指向 P，就可能引用一个已经进入空闲链表的页面。即使最终表项看起来指向了正确的地址，中间的页面释放也已经破坏分配器状态。

**权限更新与 TLB 一致性分析**

映射的状态包括目标物理页和访问权限。将新权限按位或入旧表项，只能增加某些权限位，无法完成权限撤销。例如原表项含有 `PTE_U`，本次 perm 不包含该位时，按位或会使原权限残留。本次实现使用 `pte_create(page2ppn(page), perm)` 重建表项，使权限由本次参数确定。

表项写入后，处理器可能仍缓存原地址翻译。旧 TLB 内容既可能保留原物理页，也可能保留原权限，因此同页权限更新也需要执行失效操作。`tlb_invalidate()` 将内存中的新表项与后续处理器翻译联系起来。

确认初版通过重建页表项更新权限，并在更新后使目标地址翻译失效；同时明确 get_pte 分级分配失败时可能保留已建立的中间级页表。本轮以审查和规格补充为主，核心映射函数沿用已通过编译的版本。

**测试设计与提示词完善**

| 检查对象 | 具体观察 | 可以暴露的问题 |
|----------|----------|----------------|
| 同页重映射 | 操作前后引用数和空闲页数量相同 | 多余加引用、错误释放后重新映射 |

**关键改进点总结**

本模块的提示词逐步从“实现两个函数”细化为对操作前状态、状态变化和操作后保证的描述。引用计数推演帮助明确所有权变化，权限撤销案例帮助发现表项更新遗漏，TLB 分析则把软件结构与处理器实际使用的翻译结果联系起来。

这种组织方式也有助于审查 AI 给出的代码。审查者可以按状态表检查分支覆盖，沿依赖接口追踪失败范围，再用有针对性的断言验证推导。最终保留清楚的实现依据和验证边界，使代码解释与实际运行结果能够相互对应。
