## 模块：练习 1 —— 理解内核启动中的程序入口操作

**负责人：** 2411292-张旭
**AI 工具 / 模型：** Codex / gpt-6 sol

### 第 1 次迭代

**目的：** 进一步核对 `entry.S` 中两条入口指令的作用，分析启动栈的分配及地址确定方式，并理解使用 `tail` 而非 `call` 的原因。

````markdown
我现在在做操作系统 Lab1 的练习1，需要解释 `entry.S` 中的 `la sp, bootstacktop` 和 `tail kern_init`。

我已经知道第一条指令是在设置栈指针，第二条是在跳转到内核初始化函数。你能结合项目里的 `entry.S`、`memlayout.h`、`mmu.h` 和链接脚本，帮我检查一下这两条指令的具体作用和设计原因吗？尤其是栈空间怎么分配、地址怎么确定，以及为什么这里使用 `tail` 而不是 `call`。先不要修改代码。
````

**结果：**

Codex 结合项目源码和构建产物指出：

1. `la sp, bootstacktop` 把启动栈高地址边界的地址装入 `sp`，而不是读取该地址里的数据。`entry.S` 通过 `.space KSTACKSIZE` 预留栈空间；`PGSIZE = 4096`、`KSTACKPAGE = 2`，所以启动栈大小为 8192 字节。栈向低地址增长，因此初始 `sp` 指向 `bootstacktop`。
2. `kernel.ld` 将内核入口定为 `kern_entry`，链接基址设为 `0x80200000`。Codex 给出的当前链接结果为 `bootstack = 0x80201000`、`bootstacktop = 0x80203000`，具体地址来自链接结果，而非直接写在汇编指令中。
3. `tail kern_init` 将执行权转交给 `kern_init`，不设置新的返回地址寄存器 `ra`。由于 `kern_init` 被声明为 `noreturn`，执行后不返回，因此无需使用普通 `call` 建立返回路径。Codex 还报告当前反汇编中该尾调用对应 `j kern_init`，本次未单独验证该反汇编细节。

随后执行：

```bash
riscv64-unknown-elf-nm -n bin/kernel | grep -E ' (kern_entry|kern_init|bootstack|bootstacktop)$'
```

输出为：

```text
0000000080200000 T kern_entry
000000008020000a T kern_init
0000000080201000 D bootstack
0000000080203000 D bootstacktop
```

实测结果与 Codex 给出的符号地址一致。阅读 `kern/init/init.c` 也确认 `kern_init` 被声明为 `__attribute__((noreturn))`，执行完初始化与启动输出后进入无限循环。

**问题与调整：** 本轮分析结论通过 `nm` 和源码核对得到支持，不需要修改提示词或内核代码，未发生第二轮交互。
